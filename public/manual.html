飛行記録 PWA 使い方

導入、準備するデータ、1回の飛行の操作

アプリを開く

ドローンの飛行前点検、離着陸地点、飛行後点検を、スマートフォンの中に残すアプリです。記録は端末のブラウザ内に保存され、サーバーへ自動では送られません。消えないように、このページの「書き出し」を習慣にしてください。

利用条件

  • 個人の、商用でない利用が対象です。
  • 再配布・再公開はできません。
  • 商用で使うときは、事前の許諾が必要です。
  • 初回起動で「同意して使う」を押すと、次から同じ端末では同意画面は出ません。
  • 全文はアプリの「システムデータ管理」にある「利用条件を表示」から読めます。

1. 導入

開く

スマートフォンのブラウザで https://nagakiyo3821.github.io/flight-pwa/ を開きます。

通信できる状態で一度開くと、その後は電波が弱い場所でも点検の入力ができます。気象の取得、住所の検索、地図、Google 同期だけは通信が必要です。

ホーム画面に置く（推奨）

毎回 URL を探さなくて済み、全画面で使えます。

iPhone（Safari）

  1. Safari でアプリを開く（Chrome からは追加できません）。
  2. 共有ボタンを押し、「ホーム画面に追加」を選ぶ。
  3. 名前は「飛行記録」のままで追加する。
  4. 以降はホーム画面のアイコンから開く。

Android（Chrome）

  1. Chrome でアプリを開く。
  2. メニューの「アプリをインストール」または「ホーム画面に追加」を選ぶ。
  3. 以降はアイコンから開く。

位置情報は、離陸・着陸の登録と気象セットで使います。ブラウザ、またはインストールしたアプリに、位置情報を許可してください。

初回に出るもの

利用条件の同意だけです。飛行記録や場所は、ファイルを取り込むまで空です。サンプルデータは自動では入りません。

2. 準備するデータ

アプリが扱うファイルは 5 種類です。拡張子はすべて .json です。

ファイル中身いつ要るか
masters.json操縦者名、機種、機体の識別番号、点検の選択肢使い始める前
log.json飛行ごとの点検記録過去の記録を引き継ぐとき。無ければ空で開始
pos.json場所（名前・住所・緯度経度・高度）よく飛ぶ場所を先に入れておくとき。無くても当日登録できる
tmp.json作業中の進行状態と、気象セットした時刻作業の途中を別端末へ移すとき。通常はアプリが持つ
settings.jsonGoogle ドライブ同期の有無手動の書き出しだけなら不要

旧ショートカットの log03.json のように、名前の末尾に番号が付いたファイルも、中身が同じ形式なら取り込めます。

最初に作るもの（masters）

点検の「誰が」「どの機体で」は masters.json に書いておきます。見本はリポジトリの public/data/masters.sample.json です。中身は架空です。氏名は「サンプル 一郎」「山田 太郎」、機体番号も例なので、必ず自分の値に書き換えてから取り込んでください。

見本に含まれる主な項目:

  • 操縦者・安全運航管理者の氏名（names）
  • 機種（例: Mavic2Pro / Tello / Other）と、機種ごとの識別番号（drones）
  • 飛行目的、飛行条件、障害物、風向、操縦モード、フェールセーフ、バッテリー番号などの選択肢
  • 機種によって出さない点検項目（Tello はバッテリー関連の一部を出さない、など）

編集はテキストエディタで行い、保存してからアプリへ取り込みます。氏名をその場で追加する欄もありますが、毎回使う名前と機体番号は masters に入れておくと、選択だけで済みます。

取り込み手順

  1. ホームの「システムデータ管理」を開く。
  2. 「取込」の masters を押し、書き換えた masters.json を選ぶ。
  3. 「取込完了」と出れば、その端末のマスタが置き換わります。
  4. 過去の log.json / pos.json がある場合は、同じ画面の log と pos も取り込む。
取り込みは、選んだファイルの内容で端末側を置き換えます。混ぜたいときは、先にいまのデータを書き出してから編集してください。何も引き継がない場合は、masters だけで始められます。

端末の中だけが正本

ブラウザのサイトデータを消す、別のブラウザに変える、機種変更する、と記録は続きません。飛ばない日でも、次を残してください。

  1. 「システムデータ管理」→「書出」
  2. 少なくとも log・pos・masters を保存する
  3. iCloud、Google ドライブ、PC など、端末の外に置く

iPhone では共有シートが開きます。保存できたかは、ファイルアプリで名前を確認してください。

3. ホーム画面の見方

上段の 4 つのボタンは、いつでも開けます。

ボタン用途
データリセット作業中の記録を空に戻し、続けて現在地の気象を入れ直す
システムデータ管理ファイルの取込・書出、端末内の初期化、利用条件
登録データ管理過去の飛行と、いま作業中の記録を開いて直す
場所データ管理離着陸地点の一覧・新規・修正・削除

その下の 1〜5 が、1 回の飛行の順番です。

表示意味
≫ と「設定待ち」または「時間場所設定」いまやる段
✓ と「修正可能」または「場所のみ更新」入力済み。開き直して修正できる
色が薄く「ロック中」手前の段が終わるまで開けない

タイトルの下の SR / SS / T:

  • SR … 日の出時刻（気象セットで入る）
  • SS … 日の入時刻
  • T … 最後に気象をセットした時刻からの経過秒。離陸時刻ではありません

T が空のあいだは、経過の催促は出ません。

4. 1 回の飛行

始める前（データリセット）

新しい飛行に入るとき、ホームの「データリセット」を押します。

  1. 確認で「リセット」を選ぶと、作業中の記録が空の NEW に戻ります。
  2. 続けて「現在地の気象データをセットしますか？」と出ます。「セット」を選びます。
  3. 位置情報を許可し、現在地が取れると、天候・降水確率・風向・風速・気温・日の出・日の入が入ります。
  4. このときの時刻が T の起点です。

位置の入力をやめると、気象セットは中止されます。通信に失敗したときもセットされません。点検画面の「データセット」からやり直せます。

セットから 2 時間を超えてホームを開くと、気象の入れ直しを求められます。セットから 24 時間を超えると、リセットして入れ直すことを求められます。「後で」も選べます。

1. 離陸前チェック

ロックが外れている「1.離陸前チェック」を開きます。項目はおおよそ次の塊です。

  • 環境 … 機種と識別番号、操縦者、体調、許可証・飛行日誌、安全運航管理者、飛行目的、飛行条件、障害物、第三者
  • 気象 … 天候、降水、風、気温（セット済みなら値が入っている）
  • 作動前・作動・飛行点検 … 取付、プロペラ、電源、バッテリー、リモート ID、GNSS、高度・距離の制限、灯火、カメラ、異音、スティック
  • 行を押すとその項目だけ開く
  • 全項目 … 表示中の項目を先頭から順に確認する
  • ?項目 … 空の項目だけ順に開く
  • データセット … 現在地の気象を入れ直す（記録の他の項目は消えない）
  • 説明の末尾の (?) は未入力、(値) は入力済み
  • 「正常 / 異常」は 2 択。飛行条件は複数選べます
  • リストに無い氏名・バッテリー番号は「任意の入力」から追加できます
  • 屋内を飛行条件に含めると、GNSS 捕捉数と地上風向は空でも次へ進めます
  • 機種によっては最初から出ない項目があります（例: Tello のバッテリー詳細）

必須が埋まると、ホームで 1 が ✓ になり、2 が開きます。備考（項目 63）は空でも構いません。

2. 離陸登録

「2.離陸登録」を開くと、地図で地点を決めます。

  • 青 … いまの GPS。位置そのものは動かせません。「再GPS計測」で取り直します
  • 橙 … 記録する地点。地図をタップして動かせます。青や緑からコピーもできます
  • 緑 … いちばん近い登録済みの場所

橙を登録地点として確定すると、緯度・経度・高度・住所・場所名が記録され、離陸日時が入ります。はじめての場所名なら場所一覧にも残ります。同名があるときは上書き確認が出ます。

緑と橙がおよそ 50m 以上離れているときは、橙を緑へ寄せる操作は使えません。別の場所として扱います。

一度時刻まで入ったあと、同じ段が「場所のみ更新」のときは、場所だけ直し、離陸時刻は維持します。画面を閉じると「離陸登録をキャンセルしました」となり、記録は変わりません。

3. 着陸登録

飛び終わったら「3.着陸登録」です。画面の意味は離陸と同じで、入るのは着陸側の地点と着陸日時です。飛行時間は離陸日時と着陸日時から計算されます。

4. 着陸後チェック

着陸後のバッテリー、取付、汚れ、プロペラ、フレーム、発熱、操縦装置の電池、備考を入力します。やり方は離陸前チェックと同じです。

5. データ登録

「5.データ登録」で確定します。確認のあと、記録の名前が離陸日時（年/月/日 時:分）になります。作業用の空に近い NEW が残り、次の飛行の下書きになります。

離陸日時が空のままでは登録できません。登録すると工程は離陸前チェックに戻ります。登録済みの内容は「登録データ管理」に残ります。

5. 登録データ管理

ホームの「登録データ管理」は、記録の一覧です。新しいものが上です。作業中の NEW（と NEW に日時が付いたもの）が先頭に来ます。

行を開くと、項目 1〜63 を直接直せます。

  • 作業中（NEW）には、削除・データ登録・データリセット・データセット・離陸・着陸・全項目・?項目があります
  • 本登録済みの記録には、削除・全項目・?項目があります。離陸日時を変えると、新しい日時の記録が追加され、古いキーの記録も残ります
  • 削除は確認のあと、その 1 件だけ消します

6. 場所データ管理

よく使う離着陸地点を、飛行の前に登録できます。

  • 新規場所登録 … 地図で地点を決めて名前を付ける
  • 一覧の行 … 名前、住所、緯度、経度、高度、位置精度、高度精度を直す。削除もここから

離陸・着陸の登録時に新しい名前を確定した場合も、この一覧に入ります。

7. システムデータ管理

操作結果
取込選んだ JSON で、端末内のその種類を置き換える
書出端末内の内容を log.json などに保存する
初期化確認のあと、端末内のその種類だけ空（masters は初期状態）に戻す。飛行記録の初期化は空の NEW になる
サーバー同期をオフ同期の設定だけ戻す。飛行データは消えない

「サーバー上も空で上書き」は使えません。初期化は端末の中だけです。

Google ドライブを使うとき

既定は手動の取込・書出だけです。ドライブと揃える場合だけ、次を行います。

  1. 見本 settings.google.sample.json を手元にコピーする
  2. フォルダ名（既定は drone）を、自分のドライブのフォルダに合わせる
  3. 「取込」の settings でそのファイルを選ぶ
  4. 「Google でログイン」を押し、アカウントを許可する
  5. 「Drive 疎通テスト」でフォルダが見えることを確認する
  6. 「Driveから取得（マージ）」でクラウド側を取り込む。「Driveへ送信」で端末側を送る。「双方向同期」は取得してから送信する
ログイン情報は settings ファイルには書きません。トークンを人に渡したり、リポジトリに置いたりしないでください。手動に戻すときは「サーバー同期をオフ」です。

8. うまくいかないとき

状況対処
ボタンがロック中手前の段の必須項目を埋める。場所の段なら離陸前、着陸後なら着陸登録
気象が入らない通信と位置情報を確認し、「データセット」をやり直す
地図が出ない通信できる場所で開く。タイルは国土地理院の地図
氏名や機種が出てこないmasters を取り込んだか、ブラウザを変えていないかを確認する
別の端末に記録が無い書き出した log / pos / masters を、その端末の「取込」で読む
記録が消えたサイトデータの削除や、別ブラウザで開いている。外に書き出したファイルから取り込む
24 時間たったホームの案内に従い、リセットして気象をセットし直す

アプリの版は画面右上の v で確認できます。
